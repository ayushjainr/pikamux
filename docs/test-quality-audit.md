# Test-quality audit (2026-09-24)

This is a review of whether Pika's tests would catch credible regressions, not a coverage-percentage exercise. Do not remove an identity, state-integrity, installation, or release contract merely because it uses fixtures or literal output. A test is valuable when its setup, action, and independent observation would fail for a plausible product defect. Production behavior is out of scope for this audit.

## Audit decisions

- `tests/setup_contract.rs::installed_opencode_plugin_maps_attention_and_verifies_native_rename`: **fixed**. The installed plugin is run with fake OpenCode/Bun interfaces. The test now checks the exact binary command, native rename request and readback, child exclusion, attention mapping, failed readback, and first-root-only naming. A temporary wrong-title mutation failed the test for its intended assertion.
- `tests/differential.rs::fixture_negative_mutants_are_rejected`: **removed** with its unused fixture. It changed an already-produced JSON value and tested the literal comparator, not Pika's state projection or identity resolution. The independent literal-contract tests remain.
- Six env-guarded subprocess fixture tests under `tests/consult_contract.rs`, `tests/onboarding_journey_contract.rs`, `tests/real_tmux_contract.rs`, and `src/consult.rs`: **fixed harness reporting**. Ordinary suite discovery now reports these as ignored rather than green no-ops; their parent tests explicitly execute them in child processes.
- `tests/third_party_notices_contract.rs`: **retained, renamed to reflect scope**. These are selected must-not-drop obligations. `generate-third-party.sh --check` detects stale output, but not a generator omission regenerated consistently into the checked-in notice file. This sentinel catches loss of the Rust standard-library or musl sections, or the pinned Windows dependency row. It does not prove complete legal compliance.
- `tests/update_contract.rs::github_actions_are_sha_pinned_and_release_workflow_declares_attestation`: **retained, renamed to reflect scope**. It checks static YAML markers and SHA-looking refs for `actions/*`; it does not execute a workflow or prove that release bytes were attested.
- `src/activity_feed.rs::equal_request_times_have_a_stable_identity_tiebreaker` and `src/attention.rs::stale_remote_is_never_actionable_and_priority_precedes_age`: **strengthened, focused tests passed**. Their previous assertions allowed a stable but wrong tie winner or stale remote selection. The new assertions require the expected identity.
- `src/cli.rs`: **strengthened, full inline suite passed**. Remote retry-safety now tests authoritative true and false values against conflicting local inference; board handoff checks the exact Open/Open/Quit action sequence and thread identity. A former “oversized-cache” unit test was narrowed to the actual fallback it exercises: retaining local rows and surfacing a supplied fleet error exactly. The separate fleet integration suite tests real size bounds.
- `src/files_data.rs::text_cap_is_exact_and_truncation_is_explicit`: **strengthened, full inline suite passed**. The previous test only looked for the word “truncated” and its name claimed control cleaning that this data layer does not perform. It now checks the exact retained byte boundary and notice. Rendering-layer tests cover control-byte safety.
- `src/monitor.rs`, `src/files_view.rs`, and `src/tmux.rs`: **strengthened, focused tests passed**. The consultation panel now proves its truncation receipt is actually rendered and second-Escape signals close/cancellation; the Files pane checks exact Unicode clipping, CWD after each navigation, and exact syntax-colored literal across wrapped rows. The tmux handoff test proves fallback selection follows the attention callback; a direct writer-injection assertion separately proves the fallback helper's exact terminal bytes.
- `src/providers.rs` and `src/update_check.rs`: **strengthened, focused cohorts passed (11/11 and 8/8)**. Provider lifecycle tests identify exactly which rows advance; native-name flood cleanup checks pipe HUP; app-server naming parses protocol frames and verifies provider-owned state unchanged. Update checks assert single-flight outcomes, version-scoped refetch, and worker exit after drop.
- `tests/real_tmux_contract.rs` and installation checks in `tests/update_contract.rs`: **retain**. They exercise external terminal and artifact boundaries with independent observations.

No live provider, fleet host, installed Pika, or user tmux state may be used for validation. Run executable tests through `scripts/with-test-home.sh`.

The completed declaration-level ledgers are `docs/test-audit-focused-ledger.md`, `docs/test-audit-integration-ledger.md`, and `docs/test-audit-inline-ledger.md`. The inline ledger has 495 retain / 1 fix / 0 unreviewed across Rust, Python, and Windows checks. File-level triage alone is not proof that every assertion is valuable.
